# 更好的网络搜索 · 接入教程

安装并启动后即可使用，不需要注册账号、填写密钥或修改配置文件。
匿名通道有公共限流，网络和服务商状态会影响可用性；免 Key 不代表无限额度。

## 先试一次搜索

在对话中说「搜一下 N.E.K.O 猫娘计划」，需要正文时再说「打开这个链接看看」。
打开面板「概览」，点「刷新面板」，可以查看本插件最近一次搜索的实际来源、条数和耗时。

没有记录只表示本插件尚未记录搜索，不表示网络故障。记录在插件重启后清空。
是否调用工具、调用哪个插件，仍由宿主决定。

默认搜索顺序：

```text
AnySearch → Exa → Bing → 百度
```

来源失败时会在总时间预算内尝试下一路。缓存与失败冷却会减少重复请求。
概览中的搜索顺序是当前配置生效的顺序，不是对每个来源可用性的保证。

## 面板

- **概览**：免 Key / 可选密钥模式、搜索顺序、代理策略、最近搜索和内置搜索状态。
- **设置**：「可选增强 · 密钥」默认收起；代理兼容单独显示。
- **诊断**：手动运行真实搜索探测，先看结论，再展开来源明细。不会自动修改搜索顺序。

## 内置搜索可以保留吗

可以。本插件不修改宿主源码、配置或内置插件状态，面板也不会强制你停用内置搜索。

两个搜索插件都运行时，对话可能调用任意一个。若只想使用本插件，可以自行到宿主「插件中心」
停用 `web_search`（显示名「网络搜索」），但请先了解影响：

- 当前宿主的主动聊天「窗口」信息源和话题联网增强仍调用内置 `web_search`。
- 停用后这些路径可能缺少资料，**不会自动改走本插件**。
- 重新启用后，宿主搜索网关可能仍在约 5 分钟的失败冷却中。
- 停用内置搜索也不能保证每轮都搜索，宿主仍会判断是否需要调用插件。

## 可选：Exa 密钥

密钥提供账号额度，不保证搜索更快。具体免费额度、计费和限流规则以服务商控制台为准。

1. 打开 <https://dashboard.exa.ai/api-keys>，注册或登录账号，生成 API Key。
2. 面板「设置」→「可选增强 · 密钥」→ Exa →「加一把」，粘贴完整密钥。
3. 点「保存并使用」。插件会保存并执行一次真实搜索验证；网络失败不等于密钥无效。

面板只显示密钥掩码和验证状态，不显示余额。新增密钥不会覆盖原有的其它 Exa 密钥；
重复粘贴同一把不会重复添加。多把密钥会按已有轮转策略使用，也可以移除单把或清空。
「还没测」不计入「验证通过」数量。

有 Exa 密钥且没有 AnySearch 密钥时，Exa 默认升到链首；显式设置的后端偏好仍优先。
整池失败后默认切换其它搜索来源，不再尝试 Exa 匿名档；
需要时可在「额度与回退策略」里启用一次匿名回退。

## 可选：AnySearch 密钥

1. 打开 <https://www.anysearch.com/about>，注册或登录后在控制台生成密钥。
2. 面板「设置」→「可选增强 · 密钥」→ AnySearch →「加一把」。
3. 粘贴后点「保存并使用」，插件会执行一次真实搜索验证。

AnySearch 只保存一把密钥；「更换密钥」会替换它。留空时仍使用匿名通道。
保存了 AnySearch 密钥后，Exa 不再因为有密钥而自动升到链首。
限流或网络故障不会被直接标记为密钥无效。

密钥存储在本插件的宿主托管配置里，请同样保护配置文件及其备份。
面板回显和插件主动上报只使用掩码；发往相应服务商的请求包含完整密钥。

## 搜不到时

1. 先在概览刷新，确认最近记录是否来自本插件。
2. 到「诊断」点「开始自检」。每个来源至少一次真实请求，开启代理双测时为两次，会消耗额度。
3. 展开「来源明细」，区分网络错误、限流、验证页和密钥错误。「未测」不等于不可用。
4. 必要时展开「检测选项」调整代理双测；自检结论不会自动改写配置。

默认代理策略为 `auto`，跟随系统和环境代理。DuckDuckGo 只有在链路中被配置，
且满足代理条件时才启用；它不在默认链路里。
使用 TUN + fake-ip 代理时，设置里的「代理虚拟地址放行」通常保持默认即可。
这不是关闭 SSRF 防护：字面内网 IP、localhost 和云元数据地址仍被拒绝。

本插件不会替服务商保证匿名额度或计费方式。配置密钥前，请检查自己账号的付费和自动充值设置。
